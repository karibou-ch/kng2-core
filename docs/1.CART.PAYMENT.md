# Cart — paiement

Source : `kng2-core/src/cart.service.ts`. Le moyen de paiement du panier est local. Il n'est pas posté par `saveServer`. La carte elle-même vit sur le compte (Stripe, via karibou-wallet). Le panier ne fait que retenir laquelle est sélectionnée.

## Fonctions

### `setPaymentMethod(payment)`

- Déclencheur : checkout au choix d'une carte, et quand le user change (`kng-cart-checkout` remet `null` si la carte n'est plus dans la liste). `kng-cart` reprend la carte de stable. Admin : `order-create` et la carte par défaut à la création d'abonnement.
- Opération : si `UserCard.isEqual` (même alias) avec le cache, sort. Sinon copie la carte, recalcule les frais de passerelle, sauve `CART_PAYMENT` en local.
- Finalité : la commande partira avec cet alias. Le débit se fait plus tard, au checkout, pas ici.

### `getCurrentPaymentMethod()`

- Déclencheur : checkout, revue, construction du payload de commande.
- Opération : renvoie `cache.payment`. Peut être une carte vide créée au démarrage (`new UserCard()`), avec `error: 'Unvalid instance'`.
- Finalité : savoir ce qui est sélectionné. Une carte vide n'est pas une carte du compte.

### `getCurrentGateway()` / `updateGatewayFees()`

- Déclencheur : `setPaymentMethod`, puis `subTotal` / `totalHubFees`.
- Opération : cherche dans `config.shared.order.gateway` l'entrée dont `label` égale `payment.issuer`. Sinon la passerelle par défaut, frais 0, libellé « Aucun ». `getCurrentGateway` renvoie cette passerelle seulement si le panier est prêt.
- Finalité : le taux ajouté au sous-total (frais hub + frais de la passerelle). Ce n'est pas le montant Stripe.

## Commentaire agent

- Le localStorage enregistre `cache.payment` dans `saveLocal`, et `loadCache` ne le relit pas. Après un rechargement, la carte affichée vient de `setContext` (`issuer` de la dernière commande) ou du checkout, pas du fichier local.
- `setContext` fait `cache.payment || user.payments.find(issuer)`. Comme pour l'adresse, un objet déjà présent bloque le remplacement. La carte initiale est un `UserCard` vide, donc vrai : la recherche sur le compte ne s'exécute pas tant que ce constructeur a tourné.
- `issuer` n'est pas un identifiant de carte. Deux cartes du même réseau se confondent. L'alias est l'identité (`UserCard.isEqual`).
- TWINT et `invoice` sont des issuers comme les autres pour le panier. L'interdiction TWINT sur un abonnement est dans le checkout, pas ici.
- Itération : traiter le paiement comme l'adresse. La commande ou le cache désignent un alias. La fiche chargée est celle du compte (`user.payments`), pas l'objet figé.
