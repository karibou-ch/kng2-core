# Cart — abonnements

Source : `kng2-core/src/cart.service.ts`. Deux états distincts :

- `subscriptionParams` : le formulaire local (jour, heure, fréquence, items en cours d'édition). Sauvé en localStorage, pas comme une ligne `/v1/cart`.
- `subscriptionsContent` : les contrats renvoyés par l'API. Publiés sur `subscription$`.

Les lignes d'abonnement dans `cache.items` ont `frequency`. Elles coexistent avec les lignes d'un achat simple.

## Fonctions

### `subscriptionSetParams(params, quiet?)` / `subscriptionGetParams()`

- Déclencheur : `kng-subscription-option`, listes produit en mode abonnement, revue du checkout (créneau), `kng-cart-items`. `quiet` est utilisé pendant la frappe pour ne pas sauver à chaque touche.
- Opération : remplace `cache.subscriptionParams`. Sans `quiet`, sauve `CART_SUBSCRIPTION` en local seulement.
- Finalité : le rythme choisi avant la création du contrat. Ce n'est pas le contrat Stripe.

### `subscriptionsGet()` / `subscriptionsGetAll()`

- Déclencheur : contrôle d'abonnement, listes, page Patreon. L'admin liste tout via `subscriptionsGetAll` (`GET /v1/cart/subscriptions`).
- Opération : `GET /v1/cart/subscription` pour le compte connecté. Un 401 devient une liste vide. Le résultat remplace `subscriptionsContent` et alimente `computeSubsQtyMap` au load du panier.
- Finalité : savoir quels contrats sont ouverts, et empêcher d'ajouter au panier un sku déjà couvert (`add` émet `ITEM_MAX`).

### `subscriptionCreate(params)` / `subscriptionCreatePatreon(options)`

- Déclencheur : checkout abonnement (`kng-cart-checkout`). Patreon : `kng-patreon`. Admin : `subscriptions-create`.
- Opération : `POST /v1/cart/subscription` ou `.../subscription/patreon`. Le corps est celui construit par l'écran (items, adresse, paiement, fréquence), pas un dump du cache. Si la réponse a `errors`, émet `CART_SAVE_ERROR` et ne garde pas le contrat.
- Finalité : créer le contrat. Le paiement 3DS éventuel est ensuite `subscriptionPaymentConfirm`. Le panier d'articles est vidé par `clearAfterOrder(hub, null, contract)` une fois le contrat accepté.

### `subscriptionUpdate(sid, params)`

- Déclencheur : checkout quand un contrat est déjà là, et `kng-subscription-item` après édition des quantités.
- Opération : `POST /v1/cart/subscription/:sid`. Même garde `errors` que la création.
- Finalité : mettre à jour items, rythme ou ancre. Pas de 3DS dans cet appel. Le recouvrement de paiement est un autre écran.

### `subscriptionUpdatePayment(hub, sid, payment)` / `subscriptionPaymentConfirm(sid, intent)`

- Déclencheur : confirmation 3DS dans le checkout et dans `kng-subscription-control`. Patreon confirme aussi par `subscriptionPaymentConfirm`. `subscriptionUpdatePayment` est le changement de carte (l'appel direct dans le contrôle est commenté).
- Opération : `POST .../payment` et `POST .../payment/confirm`. Le contrat en cache est remplacé par la réponse.
- Finalité : attacher la carte et terminer le SetupIntent ou le PaymentIntent. Le panier ne confirme pas le PaymentIntent Stripe lui-même. Ça reste le frontend (`confirmCardPayment` / `confirmCardSetup`).

### `subscriptionPause(subscription, to)` / `subscriptionResume` / `subscriptionCancel` / `subscriptionResetBillingCycle(subscription, toDate | 'now')`

- Déclencheur : `kng-subscription-control` pour pause et annulation. Admin : pause, reprise, reset d'ancre sur `subscriptions.page`.
- Opération : `POST .../pause` avec `{to}`, `.../resume`, `.../cancel`, `.../billingcycle` avec `{to}` ou `{to:'now'}`. Le contrat correspondant dans `subscriptionsContent` est fusionné avec la réponse, puis `subscription$` émet.
- Finalité : changer l'état du contrat sans toucher aux articles du panier.

### `subscriptionGetPatreonProducts()`

- Déclencheur : page Patreon au démarrage.
- Opération : `GET /v1/cart/subscription/patreon/products`.
- Finalité : la liste des produits proposés au soutien, distincte du catalogue du hub.

## Commentaire agent

- `subscriptionParams` et le contrat Stripe ne sont pas la même chose. Écraser l'un avec l'autre casse soit le formulaire, soit l'abonnement en cours.
- `clearAfterOrder` avec un contrat efface toutes les lignes du hub, y compris celles sans `frequency`. Sans contrat, il garde les lignes `frequency`.
- La quantité déjà abonnée bloque `add` via `getSubsQtyMap`. Cette map n'existe qu'après un `subscriptionsGet` ou un load qui a reçu `cart.subscriptions`.
- Pause, reprise, annulation et ancre ne vident pas le panier et ne changent pas l'adresse de livraison du cache.
- Ne pas confirmer un PaymentIntent de facture d'abonnement dans ce service. Le wallet ne le fait plus. Le frontend confirme avec le `client_secret`.
- TWINT n'est pas un moyen d'abonnement. Le filtre est dans le checkout (`issuer === 'twint'`), pas dans `subscriptionCreate`.
