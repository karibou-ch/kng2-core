# Cart — adresse et créneau

Source : `kng2-core/src/cart.service.ts`. L'adresse affichée au checkout est la fiche du compte. Une commande ou le localStorage ne font que désigner le lieu.

`UserAddress.isEqual` compare la rue, le nom, l'étage et le code postal. Le téléphone, la note, la région et le geo n'en font pas partie. Un téléphone différent reste la même adresse.

## Fonctions

### `accountAddress(address)` (privé)

- Déclencheur : `setShippingAddress` et `loadCache`.
- Opération : parmi `currentUser.addresses`, la première fiche `isEqual` à l'adresse proposée. Sinon le dépôt du hub courant qui a le même lieu et `fees >= 0`.
- Finalité : traduire un lieu (commande, localStorage, formulaire) en la fiche à jour du compte ou du dépôt.

### `setShippingAddress(address)`

- Déclencheur : checkout (`kng-cart-checkout.setShippingAddress`, qui normalise le téléphone avant). Sélection dans la revue. Admin : `order-create`, `subscriptions-create`.
- Opération : sans rue, vide le cache et sort. Si `accountAddress` trouve une fiche, c'est elle qui est copiée (`UserAddress.from`), pas l'objet proposé. Un dépôt d'un autre hub (`fees >= 0` sans correspondance) est rejeté. Si le lieu est déjà celui du cache, le cache est remplacé par cette fiche et la fonction sort sans `save`. Sinon elle sauve `CART_ADDRESS` (local seulement).
- Finalité : le panier pointe toujours vers l'adresse du compte quand le lieu est connu. Changer le téléphone sur la commande ne crée pas une seconde adresse.

### `getCurrentShippingAddress()`

- Déclencheur : checkout (résumé, frais, réduction multi-commandes), revue.
- Opération : renvoie `cache.address`.
- Finalité : une seule adresse courante pour l'affichage et le calcul de livraison.

### `setShippingDay(date, hours, { lastMinute? })`

- Déclencheur : calendrier (`kng-calendar`), accueil, lignes du panier. `loadCache` l'appelle aussi pour normaliser le jour restauré. Admin : date choisie dans `order-create`.
- Opération : ignore l'appel si le jour, l'heure et le drapeau last-minute sont déjà ceux du cache. Sinon mémorise les trois et sauve `CART_SHIPPING` (local seulement).
- Finalité : le créneau de la commande. `when` et `hours` restent deux champs. `hours` est l'index 10, 12 ou 16, pas l'heure extraite de la date.

### `selectLastMinuteShipping(now?)`

- Déclencheur : le choix « aujourd'hui » quand le calendrier l'autorise.
- Opération : `CalendarService.isLastMinuteAvailable`. Si non, lève une erreur. Sinon `setShippingDay` avec `lastMinute: true`.
- Finalité : une livraison le jour même, jamais restaurée depuis le localStorage (`loadCache` force `lastMinute` à faux).

### `getCurrentShippingDay` / `getCurrentShippingTime` / `isCurrentShippingLastMinute` / `getCurrentShippingTimePrice` / `isCurrentShippingDayAvailable`

- Déclencheur : navbar, accueil, listes, checkout, calcul des frais.
- Opération : lectures. Sans jour en cache, `getCurrentShippingDay` demande le prochain jour au calendrier. Le supplément d'horaire vient de `shipping.pricetime[hours]`.
- Finalité : afficher le créneau et savoir si une boutique livre ce jour-là.

### `getShippingDayForMultipleHUBs()`

- Déclencheur : pas d'écran principal. Calcul d'intersection des jours de deux hubs.
- Opération : `indexOf` sur des `Date`. Deux dates du même jour créées à part ne matchent pas.
- Finalité : prévue pour un panier multi-hub. L'intersection est fausse tant que la comparaison n'est pas `equalsDate`.

## Commentaire agent

- La fiche chargée est celle du compte, même si on compare avec `order.shipping`. Le checkout fait ce choix dans son init : `isEqual` entre la dernière commande et `user.addresses`, sinon `addresses[0]`.
- `setContext` tente encore `cache.address || order.shipping` puis `|| getDefaultAddress()`. Les deux sont morts : le cache naît avec un `DepositAddress` dont `fees` vaut 0, donc l'objet est vrai.
- `loadCache` n'applique la fiche du compte que si le localStorage a déjà une rue. Sans localStorage, il ne pose pas l'adresse par défaut.
- Même lieu : `setShippingAddress` remplace l'objet en mémoire par la fiche du compte et ne sauve pas. Le téléphone affiché change. Le localStorage ne change qu'au prochain `save` d'une autre action.
- L'étage fait partie de `isEqual`. Une commande sans l'étage du carnet ne désigne pas cette fiche. Le checkout retombe alors sur `addresses[0]`.
- Ne pas réintroduire une comparaison de téléphone, de note ou de geo pour décider si c'est « une autre adresse ».
- Itération : `load` doit appliquer la même règle que le checkout, y compris sans localStorage, et `setContext` ne doit plus écrire `order.shipping` dans `cache.address`.
